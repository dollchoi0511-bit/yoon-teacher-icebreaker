# 신규교사 공감 밸런스게임 — GitHub Pages + Firebase

## 포함 파일
- index.html: GitHub Pages에서 직접 실행하는 완성 페이지. 별도 빌드 불필요.
- firestore.rules: 밸런스게임 전용 Firestore 보안 규칙.
- README.md: 설치 및 진행 안내.

Firebase 프로젝트 `yoon-t` 설정이 index.html에 입력되어 있습니다. 관리자 비밀번호는 코드에 포함되어 있지 않습니다.

## 1. Firebase Authentication 설정
1. Firebase 콘솔에서 yoon-t 프로젝트를 엽니다.
2. Authentication → 로그인 방법에서 `익명` 및 `이메일/비밀번호`를 사용 설정합니다.
3. Authentication → 사용자 → 사용자 추가에서 관리자 이메일과 비밀번호를 등록합니다. 이미 등록되어 있다면 기존 계정을 사용합니다.
4. 관리자 계정의 UID를 복사합니다.
5. Firestore Database에서 컬렉션 `admins`를 만들고, 문서 ID를 복사한 관리자 UID로 지정합니다. 필드 `role`(문자열)을 `admin`으로 추가합니다. UID는 이메일이 아닙니다. 컬렉션 이름은 `admins`입니다.
6. Authentication → 설정 → 승인된 도메인에 `사용자명.github.io`를 추가합니다. 저장소 이름과 https://는 포함하지 않습니다.

## 2. Firestore 설정
Firestore Database를 만들지 않았다면 기본 데이터베이스 `(default)`를 생성합니다.
Firestore Database → 규칙에 firestore.rules 내용을 붙여넣고 게시합니다.

중요: 이 파일은 밸런스게임 경로 `balanceRooms`와 관리자 경로 `admins`만 정의합니다. 같은 Firebase 프로젝트에서 기존 마음 카드 앱도 운영 중이라면 기존 규칙을 전부 지우지 마세요. 기존 `rules_version` 및 `service cloud.firestore`는 유지하고, 이 파일의 `/admins/{uid}`와 `/balanceRooms/{roomId}` match 블록과 공통 함수를 기존 `/databases/{database}/documents` 안에 합쳐야 합니다. 기존 admins 규칙이 있으면 중복으로 추가하지 않고 필요한 조건을 합칩니다. 같은 경로에 허용 규칙을 중복 정의하면 둘 중 하나가 허용하는 요청은 통과합니다.

## 3. GitHub Pages 배포
1. ZIP을 풀고 index.html, firestore.rules, README.md를 저장소 루트에 업로드합니다.
2. Settings → Pages → Deploy from a branch를 선택합니다.
3. Branch: main, 폴더: / (root), Save.
4. GitHub에서 안내하는 Pages 주소를 엽니다.

index.html은 로컬 파일 더블클릭보다 GitHub Pages의 HTTPS 주소에서 실행해주세요. Firebase SDK는 인터넷 연결이 필요합니다.

## 4. 연수 진행
1. 위쪽 관리자 로그인 → Firebase에 등록한 이메일/비밀번호로 로그인합니다.
2. 연수방 만들기를 누릅니다.
3. 참가 링크 복사로 `?room=...`이 포함된 현재 링크를 공유합니다. 기본 홈페이지 주소만 공유하면 참가자가 입장할 방을 찾지 못합니다.
4. 참가자가 학교와 이름을 입력하면 입장 현황에 표시됩니다. 참가자에게 Firebase 계정을 만들라고 할 필요는 없습니다.
5. 선택 제한시간을 5~120초로 설정하고 시작하기를 누릅니다. 기본 20초입니다.
6. 1~3번은 선택만, 4~8번은 선택 후 이유 작성 팝업이 나타납니다. 선택 시간 종료 후에도 이유 작성은 가능합니다.
7. 진행자가 결과 확인을 누르면 모든 참가자에게 선택 비율과 A/B별 이유가 표시됩니다.
8. 다음 질문을 누르면 함께 이동합니다. 이유를 아직 쓰는 참가자가 있으면 진행자에게 확인창이 표시됩니다.
9. 새 연수는 새 연수방 만들기로 시작합니다. 이전 자료는 기존 방에 보관됩니다.

## 질문 구성
1. 수업 중 더 당황스러운 상황은? — 질문이 끊이지 않는 학생들 / 아무도 대답하지 않는 학생들
2. 더 긴장되는 첫 경험은? — 첫 공개수업 / 첫 시험 출제
3. 둘 중 더 끌리는 선생님은? — 학생들에게 인기 많은 선생님 / 동료 선생님들에게 인기 많은 선생님
4. 지금 더 어렵게 느껴지는 것은? — 수업 준비 / 생활지도
5. 평가에서 더 어렵게 느껴지는 것은? — 시험 출제 / 수행평가 설계
6. 학교생활에서 더 어렵게 느껴지는 것은? — 행정 업무 / 동료 선생님들과의 소통
7. 업무를 잘 모를 때 더 부담스러운 것은? — 다른 선생님께 질문하기 / 혼자 해결하려다 실수하기
8. 다음 연수에서 더 원하는 것은? — 교직 실무를 구체적으로 배우기 / 교직생활의 고민을 함께 나누기

## 저장 구조 / 동작
- admins/{관리자 UID}: 관리자 권한. 웹에서 생성하거나 수정할 수 없으며 Firebase 콘솔에서 설정합니다.
- balanceRooms/{방 ID}: 현재 질문, 진행 상태, 제한시간, 방 생성자.
- balanceRooms/{방 ID}/people/{인증 UID}: 참가자 이름.
- balanceRooms/{방 ID}/answers/{질문번호_인증 UID}: 선택과 이유.
- 약 1.2초 간격으로 Firebase 상태를 확인해 화면을 동기화합니다. 진행 버튼을 누른 후 참가 화면에 반영되기까지 약간의 지연이 있습니다.
- 참가자에게 진행 전 다른 사람의 선택과 이유는 공개하지 않습니다.
- 서버 보안 규칙이 제한시간 이후 선택, 선택 변경, 참가자의 진행 상태 변경을 차단합니다.
- 시크릿 창, 브라우저 변경, 사이트 데이터 삭제 시 익명 사용자 신원이 달라져 새 참가자로 입장할 수 있습니다.
- 각 기기의 시계가 정확해야 화면의 제한시간 표시가 맞습니다. 실제 선택 허용 여부는 Firebase 서버 시간으로 판단합니다.
- 주기적인 상태 조회 방식이므로 참가 인원과 진행 시간에 따라 Firestore 읽기 사용량이 발생합니다.

## 문제 해결
- 관리자 권한 없음: Authentication 사용자 UID와 admins 문서 ID가 같은지 확인하세요. `admis`가 아니라 `admins`입니다.
- 권한 부족/저장 실패: firestore.rules 게시 여부와 기존 규칙 병합 상태를 확인하세요.
- 익명 로그인 오류: Authentication에서 익명 로그인을 사용 설정하세요.
- 관리자 로그인 오류: 이메일/비밀번호 제공자가 켜져 있는지, 등록된 계정인지 확인하세요.
- 참가자가 기본 안내 화면만 봄: 방 ID가 포함된 참가 링크를 공유하세요.

## 검증 범위
HTML 내 JavaScript 구문 검사 및 파일 구성 검사를 수행했습니다. 사용자 Firebase 콘솔의 제공자 설정과 규칙 게시, 실제 GitHub Pages 주소에서의 여러 기기 동시 접속은 배포 후 확인해야 합니다. 이 ZIP의 데이터는 Firebase에 저장되며 이전 ChatGPT Sites 버전의 기록을 자동으로 가져오지는 않습니다.
